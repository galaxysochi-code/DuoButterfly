# Building DUO Butterfly

## Tools

An Apple silicon Mac with macOS 26+, Xcode 26.4+, and [XcodeGen](https://github.com/yonaskolb/XcodeGen).
The app has no third-party runtime dependencies.

```bash
brew install xcodegen
xcodegen generate
open DuoButterfly.xcodeproj
```

The Xcode project is generated from `project.yml` and isn't committed.

## Verification build

```bash
./build.sh check
```

Builds an unsigned arm64 Release app and prints its path.
`DUOBUTTERFLY_DERIVED_DATA` sets the build folder (default: `.build/DerivedData`).

## Installable archive

```bash
./build.sh adhoc
```

Creates `dist/DuoButterfly-v<version>-macos-arm64-adhoc.zip` containing `DUO Butterfly.app`,
plus a SHA-256 file. An existing archive with the same name is never overwritten.

An ad-hoc signature changes with every build, so macOS may ask for screen-recording permission
again. To keep the permission, sign with your own development certificate:

```bash
DUOBUTTERFLY_SIGN_IDENTITY="Apple Development: …" ./build.sh development
```

## Donation wallets

Wallet addresses for the **Say Thanks** sheet aren't stored in the repository. The app reads
`DuoButterfly/Resources/Wallets.plist` (ignored by Git); without it the banner and sheet are hidden.

For a local build, copy the example and fill in your addresses:

```bash
cp scripts/Wallets.example.plist DuoButterfly/Resources/Wallets.plist
```

Each entry has `id`, `asset`, `network`, `logo` (`bitcoin`, `ethereum`, `usdc`, `tether`, `ton`, `gram`,
`solana`), an optional network `badge`, and `address`.

Release builds get the file from the `DONATION_WALLETS_PLIST` repository secret (the plist in Base64):

```bash
base64 -i DuoButterfly/Resources/Wallets.plist | gh secret set DONATION_WALLETS_PLIST
```

## Tests

```bash
./scripts/test.sh unit   # logic, cursor, sensor, translations, wallets — used in CI
./scripts/test.sh all    # also Metal, windows, and physical-display tests
```

Run the full suite on a MacBook with an unlocked session and the built-in display on:
a full-screen animation appears briefly. `DUOBUTTERFLY_TEST_RESULTS` sets a new `.xcresult` path.

## Translations

Interface strings use Russian source text as the key: `tr("…")`. Add English, Simplified Chinese,
and Spanish entries in `DuoButterfly/Localization.swift`. `LocalizationTests` fails if any
`tr()` string is missing a translation. System permission prompts are translated in
`DuoButterfly/<language>.lproj/InfoPlist.strings`.

## README screenshots

```bash
./scripts/readme-screenshots.sh
```

Opens real app windows in English, Chinese, Spanish, and Russian and saves them to `docs/images/`.
The terminal needs screen-recording permission.

## Effect GIF

```bash
./scripts/readme-gif.sh
```

Renders `docs/images/effect.gif` with the app's Metal renderer: the lid closes and opens for each style.

## Preview image

`DuoButterfly/Resources/PreviewDesktop.png` is generated by a script:

```bash
swift scripts/draw-preview-desktop.swift DuoButterfly/Resources/PreviewDesktop.png 7 ocean
```

Palettes: `ocean`, `dusk`, `sunrise`, `lagoon`. The number picks the ribbon layout.

## Releasing

1. Update `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in `project.yml`.
2. Add a `## [x.y.z]` section to `CHANGELOG.md`.
3. Create and push a tag:

   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```

The **Release** workflow checks that the version matches the tag, runs unit tests, builds the
ad-hoc archive, and publishes it to GitHub Releases with notes from `CHANGELOG.md`.

## Diagnostics

```bash
open -n "/Applications/DUO Butterfly.app" --args --diagnostics /tmp/duobutterfly-status.json
```

Quit any running copy first. The file contains state and frame counters, never screen images.
The same report is available in the app: **Settings → Diagnostics → Copy Report**.
